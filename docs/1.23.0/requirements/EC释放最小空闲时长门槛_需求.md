# 需求分析：EC 释放规则新增"最小空闲时长"门槛

> 需求名称：EC释放最小空闲时长门槛 | 类型：功能增强（ENHANCE） | 模式：本地变更（不入 DPMS）
> 澄清纪要：`docs/1.23.0/requirements/EC释放最小空闲时长门槛_澄清纪要.md`

---

## 一、需求背景

DSS 的 EC 实例自动释放（`ECInstanceReleaseExecuteTask`）在队列资源达到高水位时，自动 kill 队列内空闲（Unlock）的 hive/spark/flink 引擎，降到低水位为止。

**现状缺陷**：候选筛选只看"是否 Unlock"，不看"空闲多久"。一个刚空闲几秒、用户马上还要用的引擎，与空了半小时的引擎一视同仁地进 kill 候选池，导致：
- 高频复用引擎被误回收，业务体感差；
- 加剧 fetch→kill 间隙的误杀（刚空闲的引擎更可能被新任务复用）。

## 二、功能点分解

### F1：规则配置新增"最小空闲时长"字段

| 项 | 说明 |
|----|------|
| 触发角色 | 工作空间管理员（规则编辑页） |
| 操作 | 在释放规则编辑弹窗新增一个数字输入框，配置"最小空闲时长(分钟)" |
| 默认 | 0（= 不限） |
| 约束 | 非负整数，最小 0，最大 10080（7 天） |
| 持久化 | 存入 `dss_ec_release_strategy.min_idle_minutes` |
| 展示 | 规则列表卡片展示该字段（>0 显示"N分钟"，0 显示"不限"） |

### F2：执行器按门槛过滤候选引擎

| 项 | 说明 |
|----|------|
| 触发时机 | 定时任务 `processStrategy` 在触发条件成立、拉取候选引擎后 |
| 行为 | 空闲时长 < minIdleMinutes 的引擎**剔除出候选池**，不进入 kill 优先队列 |
| 单位换算 | 配置分钟 × 60000 → 毫秒，与 `unlockDuration`（毫秒）比较 |
| 兼容 | minIdleMinutes = 0 时过滤恒真，等价于原行为 |

### F3：默认值全链路固化为 0

| 项 | 说明 |
|----|------|
| 后端类型 | `int`（基本类型，默认 0，不可为 null） |
| DB 约束 | `NOT NULL DEFAULT 0` |
| 前端默认 | 表单初始 / 新增重置 / 编辑回填均为 0 |
| 目的 | 杜绝 null 漂移，保证存量与新增规则行为一致 |

## 三、验收标准（AC）

### F1 验收
- **AC1.1** 规则编辑弹窗存在"最小空闲时长(分钟)"输入框，默认显示 0。
- **AC1.2** 输入框最小值 0，不能输入负数。
- **AC1.3** 保存规则后，DB `min_idle_minutes` 列写入所填值。
- **AC1.4** 规则列表卡片正确展示该字段（0→"不限"，N→"N分钟"）。
- **AC1.5** 编辑已有规则时，输入框回填 DB 中的值。

### F2 验收
- **AC2.1** minIdleMinutes=0 时，候选引擎集合与改动前完全一致（兼容）。
- **AC2.2** minIdleMinutes=5 时，空闲时长 < 5 分钟的引擎不在 kill 名单中。
- **AC2.3** minIdleMinutes=5 时，空闲时长 ≥ 5 分钟的引擎仍可被正常 kill。
- **AC2.4** 门槛过滤发生在构建 kill 优先队列之前（短空闲引擎不参与排序）。
- **AC2.5** 门槛仅在触发条件成立后才生效；触发条件不满足时不 kill（门槛无副作用）。

### F3 验收
- **AC3.1** 后端 `ECReleaseStrategy`/`ECReleaseStrategyDO` 字段类型为 `int`，无 null 可能。
- **AC3.2** DB 列为 `NOT NULL DEFAULT 0`，`ALTER TABLE` 后存量行值为 0。
- **AC3.3** 前端新增/编辑/回填三处默认均为 0。

---

## 四、范围边界

### 范围内
- 新增 `minIdleMinutes` 字段（后端 bean/DO/Mapper、DB 列、前端表单/展示/i18n）。
- `processStrategy` 候选筛选加门槛过滤。

### 范围外（明确不做）
- ❌ 不改 kill 优先队列算法（`UserFairECKillingPriorityQueue`）。
- ❌ 不改触发/终止条件判断（`satisfy` 双水位逻辑）。
- ❌ 不修 fetch→kill 的 TOCTOU 竞态（独立后续工作）。
- ❌ 不改 kill 请求体（仍只传 instance 名）。
- ❌ 不改 `LONG_TIME_THRESHOLD`（5min 排序阈值，保留）。

## 五、风险与影响

| 风险 | 等级 | 说明 / 缓解 |
|------|------|------------|
| 门槛过高导致回收失效 | 🟡 中 | N 越大，高水位时越杀不动。缓解：默认 0，用户按队列忙闲自调；文档提示权衡 |
| 存量规则兼容 | 🟢 低 | 默认 0 = 不限，ALTER 回填 0，行为零变化 |
| 字段类型选错致 null | 🟢 低 | 已用 `int` + `NOT NULL DEFAULT 0` 固化 |
| 竞态仍存在 | 🟡 中 | 本任务不修；用户已知（决策7） |
