> **重要说明**：本接口在现有 **outbound MCP 外发通道**（`/api/outbound/send`，`task_type='mcp'`）基础上扩展 **图片消息外发**（`type=image`），供 DSS 服务间直调。文本与图片同时外发：图片先存 HDFS、Qwen VL 识别成文字、与文本一起做大乔敏感检测，通过后以飞书**真图片消息**投递。

---

## 1. 概述

DataGo 在 outbound 通道扩展图片外发能力：

| 编号 | 接口 | 方法 & 路径 | 用途 |
|:----:|------|------------|------|
| ① | 图片外发任务受理 | `POST /api/outbound/send`（`type=image`） | DSS 提交文本+图片+接收人，受理后异步处理 |
| ② | 任务状态查询 | `POST /api/outbound/task` | 按 taskId 查询外发任务状态/结果 |

> ① 复用现有 `/api/outbound/send` 路径，通过 **`type=image`** + **`source=dss`** 区分图片外发子流程；现有 `type=text`/`file` 行为不变。

**Base URL**：`http://{DataGoHost}:{DataGoPort}`（默认端口 `3003`，dss url 需加 `/cui` 前缀，见项目记忆 `cuiw1-uat-api-prefix`）  
**Content-Type**（①）：`multipart/form-data; charset=utf-8`（因含图片文件上传）  
**Content-Type**（②）：`application/json; charset=utf-8`

## 2. 鉴权与通用约定

### 2.1 鉴权（DSS 服务间）

DSS 复用**页面登录 session-token**（即 `/cui` 页面进入所需的同一个 token），由 `SessionTokenService.validate` 校验，并从 `claims.username` 取 `loginUser`（同时作为图片 HDFS 上传归属用户）：

| Header | 必填 | 说明                                                     |
|--------|:----:|--------------------------------------------------------|
| `Session-Token` | 二选一 | 页面登录 session-token（①段，绑定 username）                     |
| `Authorization` | 二选一 | `Bearer <session-token>`（同上，等价形式） |

> token 校验通过后，`loginUser = claims.username`；token 无效/过期/无 username → 401。**loginUser 同时作为图片 HDFS 上传归属用户**（不再用接收人首位）。该鉴权**仅对 `source=dss` 生效**；`source=mcp`（Claude 工具调用）仍走原会话级 outbound token。

### 2.2 任务来源（source）与类型（type）

| 字段 | 取值 | 说明 |
|------|------|------|
| `source` | `mcp` / `dss` | 任务来源。`dss`=DSS 服务间调用；`mcp`=Claude 工具调用转发（现有） |
| `type` | `text` / `file` / **`image`** | 外发内容类型。**`image`** 为本期新增（文本+图片） |

> 图片外发固定 `source=dss` + `type=image`（Claude 工具链暂不发起图片外发；如后续需要可扩展 `source=mcp`）。

### 2.3 统一响应结构

```json
{
  "success": true,
  "code": 200,
  "message": "描述信息",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `success` | boolean | 业务是否成功 |
| `code` | number | HTTP 状态码 |
| `message` | string | 结果描述/错误信息 |
| `data` | object \| null | 业务数据，失败时为 `null` |

### 2.4 任务状态枚举（type=image）

| status 值 | 含义 | 是否终态 | DSS 后续动作 |
|-----------|------|:--------:|-------------|
| `pending` | 已受理，待处理 | 否 | 轮询 |
| `detecting` | 处理中（HDFS 上传 / OCR / 大乔检测） | 否 | 轮询 |
| `detected_pass` | 敏感检测通过（短暂中间态，随即投递） | 否 | 可继续轮询 |
| `detected_fail` | 命中敏感数据 | 是 | 流程终止，已通知接收人 |
| `detect_error` | 处理异常（HDFS/OCR/检测失败，已重试） | 是 | 流程终止，已通知 |
| `exported` | 已外发（飞书图片消息投递成功） | 是 | 流程完成 |
| `export_failed` | 外发投递失败 | 是 | 流程终止，已通知 |

### 2.5 通用错误码

| code | 含义 | 触发场景 |
|:----:|------|---------|
| 200 | 成功 | 正常响应 |
| 400 | 参数错误 | type 非法、text 空、图片超 10MB、recipients 空、图片缺失等 |
| 401 | 鉴权失败 | session-token 无效/过期 / 无 username |
| 413 | 文件过大 | 单张图片 > 10MB |
| 500 | 服务内部错误 | DataGo 内部异常（HDFS/OCR/飞书） |
| 502 / 504 | 上游不可达 | Qwen VL / 飞书 / Linkis 不可达 |

## 3. 接口详情

### 3.1 ① 图片外发任务受理 — `POST /api/outbound/send`（`type=image`）

**用途**：DSS 提交「文本消息 + 报表图片 + 接收人」，DataGo 受理后异步执行：图片存 HDFS → Qwen VL OCR → 「OCR 文字 + 文本」大乔检测 → 飞书图片消息投递。

**Content-Type**：`multipart/form-data; charset=utf-8`

#### 请求参数（multipart 字段）

| 字段 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `source` | string | 是 | 固定 `dss` |
| `type` | string | 是 | 固定 `image` |
| `channel` | string | 否 | 渠道，默认 `feishu`（本期图片消息仅飞书） |
| `text` | string(json field) | 是 | **文本消息内容（必填，非空）** |
| `recipients` | string(json field) | 是 | 接收人工号列表，JSON 数组字符串（如 `["alexyang","ryanchen"]`），非空。目前不接受 v_ 开头用户，不接受系统用户如 hadoop、hduser开头的 |
| `title` | string(json field) | 否 | 任务标题（用于审计/通知，空则截取 text） |
| `images` | File[] (multipart) | 否 | 报表图片文件，**每个 ≤10MB**；0~N 张（文本必填，图片可选，不限张数） |

> **字段约定**：文本类字段以 multipart 普通 form 字段提交（`recipients` 用 JSON 字符串）；图片以 `images` 字段重复多次（一图一次）提交。

**请求示例（curl）**：
```bash
curl -X POST 'http://datago:3003/api/outbound/send' \
  -H 'Authorization: Bearer <页面登录 session-token>' \
  -F 'source=dss' \
  -F 'type=image' \
  -F 'channel=feishu' \
  -F 'text=2026年7月审计数据报表，详见图片' \
  -F 'recipients=["alexyang","ryanchen"]' \
  -F 'title=7月审计报表外发' \
  -F 'images=@/path/report1.png' \
  -F 'images=@/path/report2.png'
```

#### 受理校验规则

| 规则 | 触发 | 响应 |
|------|------|------|
| source/type 校验 | source≠dss 或 type≠image | 400 |
| text 校验 | text 为空/空白 | 400（文本必填） |
| recipients 校验 | 非数组/为空；过滤系统账号与外包（`v_` 前缀）后为空 | 400 |
| 图片大小 | 任一图片 > 10MB（可配） | 413 |
| 图片格式 | 非图片扩展名（.png/.jpg/.jpeg/.gif/.webp/.bmp） | 400 |
| 鉴权 | Token 无效 / IP 非白名单 | 401 |

#### 响应（受理成功）

```json
{
  "success": true,
  "code": 200,
  "message": "外发任务已受理",
  "data": {
    "accepted": true,
    "taskId": 2048,
    "status": "pending",
    "imageCount": 2
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `data.taskId` | number | 任务 ID（= `datago_report_export_task` 主键，后续 ② 查询用） |
| `data.status` | string | 初始 `pending` |
| `data.imageCount` | number | 受理图片张数 |

#### 受理后异步处理（DataGo 内部，对 DSS 透明）

```
受理落库(pending; text→user_prompt) → 图片二进制上传HDFS(upload直传) → Qwen VL OCR → (OCR文字+text) 大乔检测
  ├─ 命中敏感 → detected_fail + 飞书通知接收人
  ├─ 异常(HDFS/OCR/检测失败) → detect_error + 飞书通知
  └─ 通过 → 飞书图片上传(download二进制取回→img_key) → 发图片消息(text+pics) → exported
```

#### 错误响应

| code | message 示例 | 触发 |
|:----:|-------------|------|
| 400 | `type 必须为 image（图片外发）` | type≠image |
| 400 | `text 不能为空` | text 缺失 |
| 400 | `recipients 不能为空` | recipients 空 |
| 400 | `图片格式不支持: xxx.exe` | 非图片扩展名 |
| 401 | `无效的 session-token 鉴权` | session-token 校验失败 / 无 username |
| 413 | `图片 report.png 超过 10MB 上限` | 单图 > 10MB |

### 3.2 ② 任务状态查询 — `POST /api/outbound/task`

**用途**：按 `taskId` 查询图片外发任务当前状态与结果摘要。

**Content-Type**：`application/json; charset=utf-8`

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `taskId` | number | 是 | ① 返回的任务 ID |
| `source` | string | 否 | 固定 `dss`（鉴权同 ①） |

```json
{ "taskId": 2048, "source": "dss" }
```

#### 响应

```json
{
  "success": true,
  "code": 200,
  "message": "查询成功",
  "data": {
    "taskId": 2048,
    "status": "exported",
    "resultSummary": "外发完成: 2张图片, 已投递 2 人",
    "sentTo": ["alexyang", "ryanchen"],
    "failedTo": [],
    "imageHdfsPaths": ["/datago/outbound/image/2048-report1.png", "/datago/outbound/image/2048-report2.png"]
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `data.taskId` | number | 任务 ID |
| `data.status` | string | 任务状态（见 2.4） |
| `data.resultSummary` | string | 状态/结果摘要 |
| `data.sentTo` | string[] | 投递成功接收人（status=exported 时） |
| `data.failedTo` | string[] | 投递失败接收人 |
| `data.imageHdfsPaths` | string[] | 图片 HDFS 存储地址（审计/回溯） |

> **字段落地说明（DSS 透明）**：上述响应字段为对外语义；底层均复用 `datago_report_export_task` **现有列**承载——`imageHdfsPaths` 来自 `report_files`、`resultSummary` 来自 `bitable_detect_summary`、`sentTo`/`failedTo` 来自 `export_result`、任务以 `task_type='mcp'`+`outbound_subtype='image'` 标识。详见设计文档 3.1。

#### 错误响应

| code | message 示例 | 触发 |
|:----:|-------------|------|
| 400 | `taskId 为必填项` | taskId 缺失 |
| 404 | `任务不存在: taskId=9999` | taskId 不存在 |
| 401 | `无效的 session-token 鉴权` | 鉴权失败 |

## 4. 端到端调用流程（DSS 编排建议）

```mermaid
sequenceDiagram
    autonumber
    participant DSS
    participant DG as DataGo
    participant HDFS as HDFS
    participant VL as Qwen VL
    participant W as 大乔(Webridge)
    participant FS as 飞书(经fass-core/weproxy)

    Note over DSS,DG: ① 受理(multipart)
    DSS->>DG: POST /api/outbound/send type=image, text, recipients, images[]
    DG-->>DSS: {taskId, status:pending}

    Note over DG: 异步处理
    DG->>HDFS: 上传图片(Linkis upload 二进制直传)
    DG->>VL: 压缩+识别图片 → 文字
    DG->>W: 检测(OCR文字 + text)
    alt 命中敏感
        DG->>FS: 飞书通知接收人(检测不通过)
        Note over DG: status=detected_fail(终态)
    else 通过
        DG->>FS: 图片上传→img_key; 发图片消息(msg+pics)
        Note over DG: status=exported(终态)
    end

    Note over DSS,DG: ② 轮询状态
    loop 每 N 秒
        DSS->>DG: POST /api/outbound/task {taskId}
        DG-->>DSS: {status, sentTo/failedTo, imageHdfsPaths}
    end
```

### 4.1 DSS 编排要点

1. **受理**（①）：multipart 提交 text + recipients(JSON) + images[]，拿 `taskId`。
2. **轮询**（②）：建议间隔 5~15 秒（OCR + 检测 + 投递，通常 < 1 分钟）。
3. **终态**：`exported`（成功）/ `detected_fail`（命中敏感）/ `detect_error`（异常）/ `export_failed`（投递失败）。
4. **失败感知**：终态失败 DataGo 已主动飞书通知接收人，DSS 无需重复通知。

### 4.2 幂等与重试

- **受理幂等**：DSS 可传业务幂等键（可选 `idempotencyKey`，本期不强制；建议 DSS 侧用 taskId 去重）。
- **重试**：`detect_error` / `export_failed` 可由 DSS 用相同内容重新受理（新 taskId）；`502/504`（上游不可达）建议退避后重试受理。

## 5. 附录

### 5.1 飞书图片消息体（fass-core，DataGo 内部组装）

DataGo 检测通过后，经 fass-core `/fass-core/feishu/external/access/sendMessage` 发送图片消息，body 结构（`DATAGO_NOTIFY` 模板，`params.pics` 携带图片）：

```json
{
  "receiver": "alexyang",
  "templateCode": "DATAGO_NOTIFY",
  "appId": "cli_a97995f452395cef",
  "params": {
    "msg": "2026年7月审计数据报表，详见图片",
    "pics": [
      { "pic": { "img_key": "img_v3_02147_02a804ec-cb05-4806-abf3-ca25da2cd27g" } },
      { "pic": { "img_key": "img_v3_02147_02a804ec-xxxx-xxxx-xxxx-xxxxxxxxxxxx" } }
    ]
  }
}
```

- `img_key` 由 DataGo 先调 fass-core 图片上传（`/fass-core/feishu/external/access/file/upload`，`fileType=message`）获得；图片字节从 HDFS 经 `downloadHDFSFile`（Linkis `/filesystem/download` 二进制直取，不 base64）取回。
- 所有 fass-core 请求附加 FS-* 鉴权 header（见需求附录 A，FS-Signature **toUpperCase**）。
- 逐 `receiver` 发送，best-effort（部分失败记 `failedTo`，不阻断）。

### 5.2 字段类型约定

| 类型 | 说明 |
|------|------|
| string | UTF-8 字符串 |
| number | 整数 |
| File[] | multipart 文件字段（`images` 重复多次） |
| 工号 | 字符串，接收人企业内工号（如 `alexyang`） |

### 5.3 关键业务约束（DSS 需知）

| 约束 | 说明 |
|------|------|
| text 必填 | 图片外发必须携带文本消息（非空） |
| 图片可选不限张数 | `images` 0~N 张，每张 ≤10MB |
| 敏感检测对象 | 「Qwen VL 识别图片所得文字 + text」整体送大乔检测，命中阻断 |
| 审批模型 | 不强制 DM 单；走事中检测 + 事后审计（与 outbound MCP 一致） |
| 飞书投递 | 真图片消息（`msg_type=image` / `params.pics`），非文件卡片 |
| 图片持久化 | 图片存 HDFS，地址入库（长期保留，可审计回溯） |
