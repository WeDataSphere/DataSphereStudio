## 二、需求背景

### 2.1 业务背景

BDAP 平台存在将库表数据外发至飞书多维表格的合规诉求。此类外发必须经过 DM 审批单（DataGo 侧审批流）授权，并在外发前完成脱敏/敏感检测，确保只有审批范围内、检测通过的数据才能落地飞书，同时外发完成后需通过飞书消息通知指定接收人。

DataGo 已提供一套通用的数据外发接口（`POST /api/export/*`），按 `optype` 区分外发对象：`optype=table` 走飞书多维表格外发，`optype=datago` 走现有报告外发（企微渠道）。本期 DSS 需作为编排方接入 `optype=table` 链路，将"DM 审批校验 → 检测 → 外发"封装为一个工作流节点，纳入 DSS 工作流统一调度。

### 2.2 现状痛点

| 痛点 | 说明 |
|------|------|
| 缺乏统一编排 | 数据外发流程散落在 DataGo 侧，无法在 DSS 工作流中与其他数据加工节点串联编排、统一调度 |
| 审批一致性难保证 | 用户在外发节点填写的库表/字段/分区/通知人是否与 DM 单审批内容一致，缺乏在执行前的强校验，存在越权外发风险 |
| 外发与通知分散 | 外发动作与飞书通知若分离处理，易出现外发成功但未通知、或重复通知的不一致问题 |
| 无受控失败语义 | 检测不通过、外发部分失败、飞书不可达等异常场景缺乏明确的失败处理与重试策略 |

### 2.3 合规诉求

- 外发必须由 DM 单驱动，节点填写的参数仅作为执行意图表达，真正执行前必须与 DataGo 返回的 DM 单信息进行一致性比对。
- 只有审批范围内（库表命中、字段一致、分区在范围内、通知人为审批用户子集）的数据方可外发。
- 检测通过前不得执行外发。

## 三、需求目标

1. **新增 AppConn 节点**：在 DSS 工作流中新增 `datagofeishu` AppConn 节点，用于编排 BDAP 数据外发到飞书多维表格的受控流程，参考 `dss-datachecker-appconn` 的实现模式。
2. **三阶段受控编排**：节点执行分为审批信息校验、检测、外发三个阶段，分别对齐 DataGo 的 ① 表单获取、② 任务生成/查询、③ 执行外发三个接口。
3. **审批一致性比对**：执行前将节点参数与 DM 单审批信息逐项比对，任一不一致即节点失败，杜绝越权外发。
4. **限定 optype=table**：本期仅处理飞书多维表格外发（`optype=table`），`optype=datago` 报告外发不在本 AppConn 范围。
5. **异步长周期执行与轮询**：节点支持异步执行与状态轮询，适配检测耗时较长的场景。
6. **一次性外发 + 飞书通知**：外发由 DataGo 一次性完成（建多维表格 + 写 sheet + 发飞书消息），DSS 不承担飞书通知职责。
7. **明确失败语义与异常码**：针对参数不一致、optype 非法、检测失败、外发失败、超时、飞书不可达等场景定义明确的失败处理与异常码。
8. **单节点多库多表**：支持单节点配置多库、多表、多字段、多分区的外发目标，外发为同一飞书多维表格的多个 sheet。

## 四、用户角色与典型场景

### 4.1 用户角色

| 角色 | 描述 |
|------|------|
| 工作流开发者 | 在 DSS 工作流中拖拽并配置 DataGo 飞书多维表格外发节点，填写 DM 单号、飞书通知人、外发目标等参数 |
| 工作流执行用户 | 触发工作流执行，节点按配置自动完成审批校验、检测、外发 |
| DM 单审批人/提单人 | 在 DataGo 侧提交 DM 审批单，确定外发范围（库表、字段、分区、optype、检测用户） |
| 飞书通知接收人 | 外发完成或检测失败时，经飞书接收外发结果消息（含多维表格 URL） |

### 4.2 典型场景（用户故事）

| 编号 | 场景 | 用户故事 |
|------|------|---------|
| US-1 | 正常外发 | 作为工作流执行用户，我希望填写审批通过的 DM 单号与外发目标后，节点自动完成检测并通过后，将数据写入飞书多维表格并通知接收人，无需人工干预 |
| US-2 | 参数不一致 | 作为工作流执行用户，当我在节点填写的字段超出 DM 单审批范围时，我希望节点在校验阶段即失败并明确提示不一致项，而不是继续执行外发 |
| US-3 | optype 非法 | 作为工作流执行用户，当 DM 单为报告外发（optype=datago）而我误用了本节点时，我希望节点直接失败并提示走现有报告外发，避免错误外发 |
| US-4 | 检测不通过 | 作为工作流执行用户，当数据命中敏感规则检测不通过时，我希望节点失败且 DataGo 已主动飞书通知，DSS 不重复通知 |
| US-5 | 外发部分失败/重试 | 作为工作流执行用户，当外发时某个 sheet 写入失败时，我希望节点按策略重试失败表，重试耗尽才失败，且已成功写入的表不回滚 |
| US-6 | 飞书不可达 | 作为工作流执行用户，当外发时飞书服务不可达（502/504）时，我希望节点按策略重试，而非立即失败 |
| US-7 | 超限不可重试 | 作为工作流执行用户，当单表数据超出飞书 sheet 大小上限时，我希望节点直接失败并提示需缩减数据，而不是无意义重试 |
| US-8 | 通知人越权 | 作为工作流执行用户，当我填写的飞书通知人不在 DM 单检测用户范围内时，我希望节点失败并提示越权用户，避免向未授权人发送外发结果 |
| US-9 | 多库多表 | 作为工作流开发者，我希望在一个节点中配置多个库的多个表（含各自字段与分区），节点分别校验并最终外发为同一多维表格的多个 sheet |

## 五、功能需求

### FR-1 工作流节点定义

- **FR-1.1** 新增工作流节点，节点类型 `linkis.appconn.datagofeishu`，节点名称"DataGo飞书多维表格外发"，AppConn 名称 `datagofeishu`。
- **FR-1.2** 节点归属"信号节点"分组，与 `datachecker` 等节点同组。
- **FR-1.3** 节点参数须至少包含以下项：

  | 参数 | 类型 | 必填 | 说明 |
  |------|------|:----:|------|
  | dmId | String | 是 | DM 审批单号 |
  | notifyUsers | String | 是 | 飞书通知人，多个用英文分号分隔；须为 DM 单检测用户的子集 |
  | dataTargets | Text | 是 | 外发目标（多库多表多字段多分区），行式 DSL（见 FR-5） |
  | detectPollInterval | Int | 否 | 检测轮询间隔（毫秒），未填用实例配置 |
  | executeRetryMax | Int | 否 | 外发失败最大重试次数，未填用实例配置 |
  | maxWaitTime | Int | 否 | 节点最大等待时间（毫秒），未填用实例配置 |

- **FR-1.4** 节点不允许用户填写飞书多维表格目标地址，实际外发目标以 DM 单和 DataGo 侧审批信息为准。

### FR-2 审批信息校验

- **FR-2.1** 节点执行首先按 DM 单号获取审批表单信息（optype、库表列表、各表授权列、分区、检测用户、当前状态），用于与节点参数比对。
- **FR-2.2** DM 单不存在（表单接口返回空数据）时节点失败。
- **FR-2.3** `optype` 必须为 `table`；为 `datago` 时节点失败并提示走现有报告外发。
- **FR-2.4** DM 单状态为终态失败（检测不通过/检测异常）时节点直接失败；为已外发时提示已外发。
- **FR-2.5** 逐外发目标命中校验：`dataTargets` 中每个目标 `(db, table)` 必须命中 DM 单审批表中的某张表，未命中时明确提示"第 N 个外发目标库表不在 DM 单审批范围内"。
- **FR-2.6** 每个目标的 `fields` 必须与该表授权列一致（默认完全一致）。
- **FR-2.7** 每个目标的 `partition` 必须在该表审批分区范围内（若 DM 单限定分区）。
- **FR-2.8** 节点填写的 `notifyUsers` 必须是 DM 单检测用户的子集，越权时节点失败。
- **FR-2.9** 字段、通知人等集合类参数在比对前统一做 trim、去空、去重、排序归一，避免因顺序或空白差异导致误判。
- **FR-2.10** 校验不通过时不进入检测与外发阶段，节点直接失败。

### FR-3 检测任务与轮询

- **FR-3.1** 审批校验通过后，进入检测阶段：首次调用任务接口时 `taskId` 传空创建检测任务，DataGo 返回唯一数值型 `taskId`，节点保存。
- **FR-3.2** 后续轮询携带已保存的 `taskId` 查询检测状态（同一接口、两种语义）。
- **FR-3.3** 状态为 `inited`/`detecting` 时继续轮询；为 `detected_pass` 时进入外发阶段；为 `detected_fail`/`detect_error` 时节点失败（终态，DataGo 已主动飞书通知，DSS 不重复通知）。
- **FR-3.4** 检测轮询间隔建议 10~30 秒，默认 30000 毫秒，可由实例配置或节点参数覆盖。
- **FR-3.5** 节点最大等待时间默认 7200000 毫秒（2 小时），超过仍未到终态则节点失败（检测超时）。
- **FR-3.6** 首次创建任务未返回 `taskId` 时节点失败。

### FR-4 执行外发

- **FR-4.1** 检测通过后进入外发阶段，调用执行外发接口，`optype=table`，传入 `taskIds=[本节点检测 taskId]`，仅导出本节点检测通过的表，避免误导出同 DM 单其他任务。
- **FR-4.2** 外发由 DataGo 一次性完成：创建飞书多维表格 + 写 sheet + 向 `notifyUsers` 发送飞书消息（含多维表格 URL）。DSS 不承担飞书通知职责。
- **FR-4.3** 外发成功（所有 sheet 成功）时节点成功，记录多维表格 URL 与各 sheet 行数。
- **FR-4.4** 飞书不可达（502/504）时按重试策略重试，重试耗尽则节点失败。
- **FR-4.5** 超出大小限制（413）或状态冲突/optype 不支持（409）时不可重试，节点直接失败。
- **FR-4.6** 部分表失败（响应 200 但存在 failed sheet）时按重试策略重试失败表，**已写入的表不回滚**；重试耗尽仍失败则节点失败。
- **FR-4.7** DataGo 内部错误（500）时节点失败。

### FR-5 单节点多库多表多字段多分区

- **FR-5.1** 节点支持通过 `dataTargets` 行式 DSL 配置多个外发目标，每行一个目标，格式为：

  ```
  dt.序号=db=库名|table=表名|fields=字段1,字段2|partition={分区值}
  ```

  - 行间用分号或换行分隔；行内各段用首个 `=` 切 key/value。
  - `db`/`table`/`fields` 必填，`fields` 多字段用英文逗号分隔。
  - `partition` 可选：值为 `{..}` 时取花括号内内容（保护分区值本身的 `=`/`/`，如多级分区 `{dt=20260716/country=us}`）；写 `partition=` 或省略表示非分区表。

- **FR-5.2** 同一 `(db, table)` 不允许重复，否则节点失败。
- **FR-5.3** 逐目标与 DM 单审批表比对（库表命中、字段一致、分区在范围内）。
- **FR-5.4** 检测阶段按 `tables` 批量创建一次检测任务。
- **FR-5.5** 外发阶段按 `taskIds` 批量外发为同一飞书多维表格的多个 sheet。

### FR-6 兼容回退

- **FR-6.1** 节点未填写 `dataTargets` 时，兼容旧的单值字段 `dbName`/`tableName`/`fields`/`partition`，自动包装为单元素目标。
- **FR-6.2** 旧节点升级后不破坏原有语义，无需用户迁移配置。

### FR-7 节点参数 UI 与实例配置

- **FR-7.1** 在工作流节点开发页面注册专属属性 UI，包括：DM 单号、飞书通知人、库名、表名、字段名称、分区名，以及可选的检测轮询间隔、外发重试次数、最大等待时间。
- **FR-7.2** 专属属性与公共属性（节点名、节点描述、业务标签、应用标签、是否复用引擎）复用已有 UI 定义机制。
- **FR-7.3** 实例级运行配置（DataGo 地址含默认端口 3003、轮询间隔、重试次数、重试间隔、最大等待时间、HTTP 连接/读取超时）写入 AppConn 实例配置，执行时读取，方式与 `datachecker` 一致。

### FR-8 日志与审计

- **FR-8.1** 节点执行过程记录关键信息：dmId、optype、库名、表名、字段数量、分区、通知人数、taskId、当前阶段、DataGo 返回状态。
- **FR-8.2** 外发完成后记录多维表格名称、多维表格 URL、各 sheet 表名/行数/状态、实际通知用户、外发完成时间。
- **FR-8.3** 不记录 DataGo 返回的原始数据内容；不记录飞书凭据；飞书通知人仅记录账号标识。
- **FR-8.4** 审计字段至少包含：执行 ID、节点 ID、执行用户、dmId、optype、taskId、库表、字段、分区、通知人、检测状态、外发状态、多维表格 URL、各 sheet 结果摘要、失败原因。

### FR-9 失败语义与异常码

按业务场景定义失败语义，异常码分配如下（业务含义映射，详细对应见设计文档 4.3）：

| 异常码 | 业务含义 | 典型场景 |
|--------|---------|---------|
| 82001 | 节点参数缺失或格式错误 | dmId/notifyUsers/库表等缺失或格式错误 |
| 82002 | 审批表单获取失败 | 表单接口调用异常或 DM 单不存在 |
| 82003 | DM 单信息与节点参数不一致 | optype≠table、表不在 DM 单、字段超范围、notifyUsers 越权 |
| 82004 | 检测任务接口调用失败 | 任务创建/查询异常或未返回 taskId |
| 82005 | 检测不通过 | 检测命中敏感（DataGo 已通知，DSS 不重复通知） |
| 82006 | 检测异常或轮询超时 | 检测异常（DataGo 已重试 2 次仍失败）或超过最大等待时间 |
| 82007 | 执行外发接口调用失败 | 飞书不可达/内部错误且重试耗尽 |
| 82008 | 外发部分表失败 | 存在 failed sheet 且重试耗尽（已写入不回滚） |
| 82009 | 外发超限或状态冲突 | 单 sheet 超 50MB / 状态冲突 / optype 不支持（不可重试） |

## 六、非功能需求

### 6.1 性能

- 节点采用异步长轮询模式执行，避免阻塞调度线程。
- 检测按表分批进行，每批 ≤ 5000 行（DataGo 侧控制）。
- 单个飞书 sheet 默认上限 50MB，超限不可重试。
- 外发由 DataGo 一次性完成，单表过大时分多次请求追加写入同一 sheet。
- 关键超时与间隔可配置（连接超时、读取超时、轮询间隔、重试间隔、最大等待时间）。

### 6.2 安全

- **审批一致性**：节点参数必须与 DM 单审批信息一致方可执行。
- **optype 控制**：仅 `optype=table` 走本 AppConn。
- **外发前置**：检测通过前不执行外发。
- **taskId 控制**：首次创建传空，后续查询与外发均使用 DataGo 返回的唯一 taskId。
- **notifyUsers 越权控制**：必须为 DM 单检测用户子集。
- **凭据隔离**：DSS 不持有飞书凭据，FS-* 鉴权与飞书访问由 DataGo 经 QZ 区 weproxy-nginx 完成。
- **日志脱敏**：不打印原始数据与凭据。
- **失败感知不重复通知**：检测不通过/异常时 DataGo 已通知，DSS 不重复通知。

### 6.3 可靠性

- 外发失败按重试策略重试：502/504 可重试，413/409 不可重试。
- 部分失败不回滚：已写入的 sheet 不回滚，仅重试失败表。
- 任务创建幂等：同一 DM 单若已有进行中任务，建议先查再创建，避免重复（依赖 DataGo 侧创建幂等）。

### 6.4 兼容性

- 运行环境：JDK 8、Spring Boot 2.7.18。
- 配置读取方式与 `datachecker` 一致（AppConn 实例 `enhance_json`）。
- 升级安装不破坏现有 `appconn_id`，应采用 update/insert ignore 或版本升级脚本方式处理，不直接删除重建。
- 旧节点（单值字段）兼容回退，升级后不破坏。

### 6.5 可观测性

- 全流程日志与审计字段记录（见 FR-8）。
- 节点状态可在工作流执行态查询。

## 七、接口需求

节点通过 DataGo 通用外发接口（`POST /api/export/*`，默认端口 3003）完成三阶段编排，接口契约详见 [接口文档 v1.1](../design/数据外发飞书多维表格_接口文档.md)。本节仅概括用途、调用时序与关键契约。

### 7.1 三个接口用途与调用时序

| 编号 | 接口 | 用途 | 调用时机 |
|:----:|------|------|---------|
| ① | `POST /api/export/form` | 按 DM 单号查询审批表单（optype/库表/字段/分区/检测用户/状态） | 节点提交后、审批校验阶段 |
| ② | `POST /api/export/task` | 同一接口两种语义：`taskId` 空=创建检测任务；`taskId` 非空=查询状态 | 审批通过后创建；之后轮询 |
| ③ | `POST /api/export/execute` | 检测通过后批量外发（建多维表格+写 sheet+飞书消息） | 检测通过后 |

调用时序：①（表单获取）→ ②（创建，taskId 空）→ ②（轮询，taskId 非空，直到终态）→ ③（外发）。

### 7.2 关键契约

- **optype 限定**：本期仅 `optype=table`；`optype=datago` 在 ① 比对阶段即拒绝，③ 返回 409。
- **统一响应结构**：`{success, code, message, data}`，`code` 与 HTTP 状态码一致。
- **任务状态枚举**：`inited`/`detecting`（非终态，继续轮询）、`detected_pass`（可外发）、`detected_fail`/`detect_error`（终态失败，DataGo 已通知）、`exported`（已外发）。
- **taskId 双语义**：空创建、非空查询；taskId 为数值型，后续 ② 查询与 ③ 外发均使用。
- **taskIds 控制**：节点传 `taskIds=[本节点 taskId]`，仅导出本节点检测通过的表。
- **notifyUsers 契约**：③ 必填非空，且须为 DM 单检测用户子集，否则 403。
- **错误码语义**：400 参数错误、403 权限/校验失败、404 不存在、409 状态冲突/optype 不支持、413 超限（不可重试）、500 内部错误、502/504 上游不可达（可重试）。
- **部分失败不回滚**：③ 响应 200 但 sheets 含 failed 时，已写入表不回滚，DSS 可据 sheets 重试失败表。
- **创建幂等建议**：同一 DM 单已有进行中任务时，建议先查再创建。

> 完整字段表与请求/响应示例见接口文档 v1.1，本需求文档不重复罗列。

## 九、验收标准

| 编号 | 验收项 | 验证方式 |
|------|--------|---------|
| AC-1 | 正常外发流程：填写审批通过的 DM 单与一致参数，节点依次完成审批校验→检测通过→外发成功，飞书多维表格创建、数据写入、通知人收到飞书消息 | 端到端执行，校验多维表格 URL 与各 sheet 行数 |
| AC-2 | 参数不一致：节点字段超出 DM 单审批范围时，节点在校验阶段失败（82003），明确提示不一致项，不进入检测/外发 | 构造字段超范围场景 |
| AC-3 | optype 非法：DM 单为 optype=datago 时，节点失败（82003），提示走现有报告外发 | 使用 datago 类型 DM 单 |
| AC-4 | 检测不通过：检测返回 detected_fail 时节点失败（82005），DataGo 已飞书通知，DSS 未重复通知 | 构造命中敏感数据场景 |
| AC-5 | 检测异常/超时：检测返回 detect_error 或超过最大等待时间时节点失败（82006） | 模拟检测异常或调小 maxWaitTime |
| AC-6 | 外发成功：检测通过后外发，所有 sheet success，节点成功，记录 bitableUrl 与各 sheet 行数 | 正常外发场景 |
| AC-7 | 外发部分失败重试：外发响应 200 但存在 failed sheet，按重试策略重试失败表；重试后成功则节点成功，重试耗尽则节点失败（82008），已写入表不回滚 | 模拟单 sheet 写入失败 |
| AC-8 | 飞书不可达重试：外发返回 502/504 时按重试策略重试，重试耗尽则节点失败（82007） | 模拟飞书不可达 |
| AC-9 | 超限不可重试：单 sheet 超 50MB 返回 413 时节点直接失败（82009），不重试 | 构造超大数据量表 |
| AC-10 | notifyUsers 越权：通知人不在 DM 单检测用户范围内时节点失败（82003），提示越权用户 | 填写非子集通知人 |
| AC-11 | 多库多表：单节点配置多个库的多个表（含各自字段与分区），逐目标校验通过后批量检测、批量外发为同一多维表格多个 sheet | 配置多目标 dataTargets |
| AC-12 | 兼容旧节点：未填 dataTargets 仅填 dbName/tableName/fields/partition 的旧节点，自动包装为单目标正常执行 | 使用旧单值参数 |
| AC-13 | 节点 kill：节点被杀死后状态置为 KILLED，不再继续轮询 DataGo | 执行中 kill 节点 |
| AC-14 | 日志审计：日志包含 dmId/optype/库表/字段数/分区/通知人数/taskId/阶段/状态/③ bitableUrl 与各 sheet 行数状态，且不含原始数据与凭据 | 检查执行日志与审计字段 |
| AC-15 | 同(db,table)重复：dataTargets 中存在相同库表时节点失败 | 配置重复目标 |

## 十、范围与非目标

- **本期范围**：仅 `optype=table`（飞书多维表格外发）。
- **非目标 1**：`optype=datago` 报告外发走现有 `/api/report/*`，不在本 AppConn 处理。
- **非目标 2**：不引入新的数据库表，复用 `dss_appconn`/`dss_appconn_instance`/`dss_workflow_node`/`dss_workflow_node_ui` 等现有表。
- **非目标 3**：DSS 侧不实现飞书通知，外发与飞书消息均由 DataGo 完成。
- **非目标 4**：节点不允许用户填写飞书多维表格目标地址。
- **非目标 5**：不实现 DSS 侧的飞书凭据管理（FS-* 鉴权由 DataGo 内部处理）。

### 11.1 新增模块

新增 AppConn 模块 `dss-datagofeishu-appconn`（路径 `dss-appconn/appconns/dss-datagofeishu-appconn`），参考 `dss-datachecker-appconn` 结构，预期包含：

| 类别 | 概要 |
|------|------|
| AppConn 入口与开发标准 | 注册 DevelopmentIntegrationStandard，提供 RefExecutionOperation |
| 节点执行编排 | 负责提交/状态/结果/杀死/进度/日志，含三阶段状态机与长轮询 |
| 执行动作 | 保存执行状态、taskId、阶段、轮询次数、外发重试次数、异常信息 |
| 接口客户端 | 封装 DataGo ①②③ 接口调用、统一响应解析、超时与重试 |
| 参数/响应模型 | 节点参数、表单、任务、外发响应、sheet 结果等实体 |
| 工具类 | HTTP 请求与响应处理 |
| 资源文件 | init.sql、appconn.properties、log4j2.xml |

> 具体类名与实现见设计文档第三章，本需求文档不展开。

### 11.2 数据库与配置

- **init.sql**：注册 AppConn 元信息、AppConn 实例（含实例级运行配置）、工作流节点定义、节点所属分组绑定、节点属性 UI 及其与节点的绑定关系。升级安装时不直接删除导致 appconn_id 变化，采用 update/insert ignore 或版本升级脚本。
- **appconn.properties**：DataGo 接口地址（含默认端口 3003）及轮询/重试/超时配置。

### 11.3 外部依赖

- **DataGo 数据外发服务**：默认端口 3003，提供 `POST /api/export/*` 三个接口。

### 11.4 部署影响

- 安装新的 AppConn 包 `datagofeishu`。
- 配置 DataGo 接口地址（含端口 3003）。
- 执行 init.sql 注册节点与 UI。
