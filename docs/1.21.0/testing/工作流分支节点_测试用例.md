# 工作流分支节点测试用例

## 1. 文档信息
- 版本：1.21.0
- 范围：`workflow.branch`（发布到 Schedulis 的 decision 方案）
- 语义口径：严格对齐 DSS FlowExecution

## 2. 测试范围
- 分支节点规则配置与保存
- `branch.rules` -> `decision` 属性映射
- 上游变量传递与分支命中
- 下游节点 `scheduled / skipped / waiting / failed链路` 判定
- 混合上游场景（编号10）

## 3. 前置条件
- 环境已部署本次分支节点改造版本
- 工作流编辑器可创建 `workflow.branch`
- 发布后可查看 Schedulis `.job` 内容与执行状态

## 4. 核心测试用例

### TC_001 分支节点可创建
1. 在画布拖入 `workflow.branch`
预期：创建成功，属性面板可见 `branch.rules`

### TC_002 `branch.rules` 可保存并回显
1. 配置规则：`amount>100=A;default=B`
2. 保存并重新打开
预期：规则内容完整回显

### TC_003 发布后分支节点为 decision
1. 发布包含分支节点的工作流
2. 查看分支节点 `.job`
预期：存在 `type=decision`

### TC_004 规则映射为 decision 属性
1. `branch.rules=b==200=sql_1345;b<50=sql_9000`
2. 发布并查看 `.job`
预期：
- `condition.1=b==200`
- `on.success.1=sql_1345`
- `on.failure.1=`
- `condition.2=b<50`
- `on.success.2=sql_9000`
- `on.failure.2=`

### TC_005 `default` 规则映射
1. `branch.rules=b==200=A;default=B`
2. 发布并查看 `.job`
预期：存在 `condition.N=true` 且 `on.success.N=B`

### TC_006 上游变量可用于分支判断
1. 上游 SQL：`select 1200 as amount`
2. 分支规则：`amount>1000=A;default=B`
3. 执行
预期：命中 `A`

### TC_007 命中下游进入 scheduled
1. 使用 TC_006 场景
预期：`A` 进入 `scheduled/running/succeed`

### TC_008 未命中兄弟下游进入 skipped
1. 使用 TC_006 场景
预期：`B` 进入 `skipped`

### TC_009 无命中且无默认规则
1. `branch.rules=amount>1000=A;amount<10=B`
2. 数据 `amount=50`
预期：分支节点失败（无可选路径）

### TC_010 混合上游场景（严格 DSS 语义）
场景：节点 X 同时有两个上游
- 普通上游 A：执行成功
- 分支上游 B：未命中 X

预期：**X 必须 `skipped`**（分支未命中优先，不因普通上游成功而执行）

### TC_011 父节点未全部完成时等待
1. 节点 X 的父节点存在未完成
预期：X 保持 `pending/waiting`，不提前执行或跳过

### TC_012 普通父节点失败链路
1. 节点 X 的普通父节点失败
预期：X 不执行，流程进入失败链路语义

## 5. 判定矩阵回归（与需求文档第5章对齐）
- 必测矩阵点：1, 2, 3, 4, 5, 8, 9, 10, 11, 12
- 强制点：编号10 必须为 `skip`

## 6. 回归关注点
- 非分支节点发布行为不回归
- decision 节点不输出 linkis 专用字段
- 变量传递能力不回归（上游输出 -> 分支条件可读）
