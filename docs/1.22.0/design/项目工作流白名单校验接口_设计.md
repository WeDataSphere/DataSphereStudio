# 项目工作流白名单校验接口_设计

## 一、设计概述

### 1.1 设计目标
新增白名单校验REST接口，供前端调用以判断指定项目或工作流是否在白名单中，前端据此动态控制项目复制和工作流复制按钮的显隐。

### 1.2 设计范围
- **dss-framework-project-server-webank**：新增白名单校验REST接口
- **前端页面**：项目列表和工作流页面调用接口控制复制按钮

### 1.3 影响接口
| 接口 | 路径 | 说明 |
|-----|------|------|
| checkIsWhite（新增） | /dss/framework/project/checkIsWhite | 白名单校验 |

## 二、现状分析

### 2.1 白名单Service现状

**类**：`ProjectOrchestratorWhiteService`
**实现类**：`ProjectOrchestratorWhiteServiceImpl`
**位置**：`dss-orchestrator/orchestrators/dss-workflow/dss-workflow-server/src/main/java/com/webank/wedatasphere/dss/workflow/service/`

#### 2.1.1 核心方法
```java
public interface ProjectOrchestratorWhiteService {
    // 判断项目或编排是否在白名单中
    boolean checkProjectAndOrchestratorIsWhite(Long projectId, Long orchestratorId);

    // 根据projectId和orchestratorId查询白名单记录
    ProjectOrchestratorWhite selectByProjectId(Long projectId, Long orchestratorId);

    // 获取项目下所有白名单记录
    List<ProjectOrchestratorWhite> getWhiteListByProjectId(Long projectId);

    // 添加白名单记录
    void addProjectOrchestratorWhite(ProjectOrchestratorWhite projectOrchestratorWhite);

    // 删除白名单记录
    void deleteProjectOrchestratorWhite(Long projectId, Long orchestratorId);
    void deleteProjectWhite(Long projectId);
}
```

#### 2.1.2 核心方法实现
```java
@Override
public boolean checkProjectAndOrchestratorIsWhite(Long projectId, Long orchestratorId) {
    if(projectId == null || orchestratorId == null){
        logger.info("projectId or orchestratorId is null, project is {}, orchestrator is {}", projectId, orchestratorId);
        return false;
    }
    ProjectOrchestratorWhite projectOrchestratorWhite = selectByProjectId(projectId, orchestratorId);
    logger.info("projectOrchestratorWhite is {}", projectOrchestratorWhite);
    return projectOrchestratorWhite != null;
}
```

### 2.2 Mapper层SQL
**Mapper**：`ProjectOrchestratorWhiteMapper`
**XML**：`ProjectOrchestratorWhiteMapper.xml`

#### selectByProjectId SQL
```sql
SELECT * FROM dss_project_orchestrator_white
WHERE project_id = #{projectId}
  AND orchestrator_id IN (0, #{orchestratorId})
ORDER BY id DESC LIMIT 1;
```

此SQL同时匹配项目级白名单（orchestrator_id=0）和工作流级白名单（orchestrator_id=具体编排ID），满足"项目在白名单中则其下所有工作流均在白名单中"的业务规则。

### 2.3 现有白名单调用场景

| 场景 | 接口 | 调用方式 |
|-----|------|---------|
| 工作流节点Spark版本控制 | /dss/workflow/listNodeType | 内嵌在NodeRestfulApi中 |
| 项目复制白名单继承 | /dss/framework/project/copyProject | 内嵌在copyProject方法中 |
| 工作流复制白名单继承 | /dss/framework/orchestrator/copyOrchestrator | 内嵌在copyOrchestrator方法中 |
| 批量编辑白名单校验 | /dss/workflow/listNodeType（POST） | 内嵌在listNodeType方法中 |

### 2.4 问题分析
- 白名单校验方法已存在但没有独立REST接口暴露给前端
- 前端无法在前端页面加载时判断项目/工作流是否在白名单中
- 需要新增一个轻量级GET接口供前端调用

## 三、详细设计

### 3.1 设计方案

在 `WebankDSSFrameworkProjectRestfulApi` 中新增 `checkIsWhite` 接口，复用已有的 `ProjectOrchestratorWhiteService.checkProjectAndOrchestratorIsWhite()` 方法。

#### 3.1.1 方案优势
- 复用现有Service层代码，无需新增Service方法
- 接口轻量级，仅返回布尔值
- 遵循现有代码风格和架构

### 3.2 接口设计

#### 3.2.1 接口定义

**文件**：`dss-framework/dss-framework-project-server-webank/src/main/java/com/webank/wedatasphere/dss/framework/project/restful/WebankDSSFrameworkProjectRestfulApi.java`

**新增方法**：
```java
/**
 * 校验项目或工作流是否在白名单中
 */
@GetMapping(path = "/checkIsWhite")
public Message checkIsWhite(@RequestParam(value = "projectId", required = false) Long projectId,
                            @RequestParam(value = "orchestratorId", required = false) Long orchestratorId) {
    String username = SecurityFilter.getLoginUsername(request);

    boolean isWhite = false;
    if (projectId != null) {
        // orchestratorId为空时默认传0，表示校验项目级白名单
        Long orchId = orchestratorId != null ? orchestratorId : 0L;
        isWhite = projectOrchestratorWhiteService.checkProjectAndOrchestratorIsWhite(projectId, orchId);
    }

    LOGGER.info("user {} checkIsWhite, projectId: {}, orchestratorId: {}, isWhite: {}",
            username, projectId, orchestratorId, isWhite);

    return Message.ok().data("isWhite", isWhite);
}
```

#### 3.2.2 接口规范

**请求**：
- **URL**：`/dss/framework/project/checkIsWhite`
- **Method**：GET
- **认证**：SSO登录认证

**请求参数**：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|-------|------|------|-------|------|
| projectId | Long | 否 | null | 项目ID，为空时返回isWhite=false |
| orchestratorId | Long | 否 | 0 | 编排ID，0表示项目级白名单校验 |

**响应**：

| 参数名 | 类型 | 说明 |
|-------|------|------|
| isWhite | Boolean | 是否在白名单中 |

**响应示例**：
```json
{
  "method": "/dss/framework/project/checkIsWhite",
  "status": 0,
  "message": "OK",
  "data": {
    "isWhite": true
  }
}
```

### 3.3 校验逻辑流程

```
checkIsWhite(projectId, orchestratorId)
│
├─ projectId == null
│  └─ return isWhite = false
│
├─ orchestratorId == null
│  └─ 设定 orchestratorId = 0
│
└─ 调用 ProjectOrchestratorWhiteService.checkProjectAndOrchestratorIsWhite(projectId, orchestratorId)
   │
   ├─ projectId == null || orchestratorId == null
   │  └─ return false
   │
   └─ 执行 SQL: SELECT * FROM dss_project_orchestrator_white
              WHERE project_id = #{projectId}
              AND orchestrator_id IN (0, #{orchestratorId})
              ORDER BY id DESC LIMIT 1
      │
      ├─ 查询结果 != null
      │  └─ return true  （在白名单中）
      │
      └─ 查询结果 == null
         └─ return false （不在白名单中）
```

### 3.4 前端集成设计

#### 3.4.1 项目列表页面
```javascript
// 页面加载时，对每个项目调用白名单校验
async function checkProjectWhite(projectId) {
  const res = await api.get('/dss/framework/project/checkIsWhite', {
    params: { projectId, orchestratorId: 0 }
  });
  return res.data.isWhite;
}

// 根据返回结果控制复制按钮显隐
project.isWhite = await checkProjectWhite(project.id);
// v-if="project.isWhite" 显示复制按钮
```

#### 3.4.2 工作流页面
```javascript
// 页面加载时，对每个工作流调用白名单校验
async function checkOrchestratorWhite(projectId, orchestratorId) {
  const res = await api.get('/dss/framework/project/checkIsWhite', {
    params: { projectId, orchestratorId }
  });
  return res.data.isWhite;
}

// 根据返回结果控制复制按钮显隐
orchestrator.isWhite = await checkOrchestratorWhite(project.id, orchestrator.id);
// v-if="orchestrator.isWhite" 显示复制按钮
```

## 六、部署方案

### 6.1 部署步骤
1. 编译打包：`mvn clean package -DskipTests`
2. 停止服务：`sh $DSS_HOME/sbin/dss-stop-all.sh`
3. 替换jar包
4. 启动服务：`sh $DSS_HOME/sbin/dss-start-all.sh`
5. 更新前端代码

### 6.2 回滚方案
- 保留原jar包备份
- 如有问题，回滚至原版本即可
- 前端恢复屏蔽复制按钮的状态

### 6.3 配置变更
无需配置变更

## 七、风险评估

### 7.1 风险项
| 风险项 | 影响 | 概率 | 应对措施 |
|-------|------|------|---------|
| 前端频繁调用导致数据库压力 | 中 | 低 | 白名单数据量小，查询走索引，性能可控 |

- **向后兼容**：新增接口不影响现有功能
- **数据兼容**：白名单表结构不变
