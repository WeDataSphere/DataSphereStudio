# 项目工作流白名单校验接口_需求

## 一、功能概述

### 1.1 需求类型
新增功能（NEW）

### 1.2 需求描述
新增一个白名单校验接口，供前端调用以判断指定项目或工作流是否在白名单中。前端根据接口返回结果决定是否展示项目复制和工作流复制功能按钮：
- **在白名单中**：展示复制按钮，允许用户执行复制操作
- **不在白名单中**：隐藏复制按钮，禁止用户执行复制操作

### 1.3 基础模块
- **模块名称**：白名单校验接口
- **涉及模块**：
  - `dss-framework-project-server-webank`：项目复制白名单校验
  - `dss-framework-orchestrator-server`：工作流复制白名单校验

### 1.4 当前痛点
当前前端将项目复制和工作流复制功能直接屏蔽，所有用户均无法使用复制功能。实际业务中，白名单内的项目和工作流是允许复制的，但前端无法判断当前项目/工作流是否在白名单中，导致：
- 白名单内的项目和工作流也无法复制，影响正常业务流程
- 需要后端提供一个接口，让前端动态判断是否展示复制按钮

## 二、现有功能描述

### 2.1 白名单机制现状
DSS系统已存在白名单表 `dss_project_orchestrator_white`，用于控制项目和工作流的特殊权限。当前白名单主要用于以下场景：

#### 2.1.1 工作流节点Spark版本控制
- **接口**：`/dss/workflow/listNodeType`（GET/POST）
- **逻辑**：调用 `ProjectOrchestratorWhiteService.checkProjectAndOrchestratorIsWhite()` 判断是否在白名单，白名单内的项目/工作流可选择Spark版本

#### 2.1.2 项目复制白名单继承
- **接口**：`/dss/framework/project/copyProject`
- **逻辑**：复制项目时，如果源项目在白名单中，复制后的项目也自动加入白名单

#### 2.1.3 工作流复制白名单继承
- **接口**：`/dss/framework/orchestrator/copyOrchestrator`
- **逻辑**：复制工作流时，如果源工作流在白名单中，复制后的工作流也自动加入白名单

### 2.2 白名单数据模型

#### 表结构：dss_project_orchestrator_white
| 字段名 | 类型 | 说明 |
|-------|------|------|
| id | BIGINT(20) | 主键ID，自增 |
| project_id | BIGINT(20) | 项目ID |
| project_name | VARCHAR(255) | 项目名称 |
| orchestrator_id | BIGINT(20) | 编排ID（0表示项目级白名单） |
| orchestrator_name | VARCHAR(255) | 编排名称（*表示项目级白名单） |
| create_time | DATETIME | 创建时间 |
| update_time | DATETIME | 更新时间 |
| create_by | VARCHAR(255) | 创建人 |
| update_by | VARCHAR(255) | 更新人 |
| reason | TEXT | 原因 |
| type | VARCHAR(50) | 类型 |

### 2.3 已有Service方法
`ProjectOrchestratorWhiteService` 已提供以下方法：

| 方法名 | 参数 | 返回值 | 说明 |
|-------|------|-------|------|
| checkProjectAndOrchestratorIsWhite | Long projectId, Long orchestratorId | boolean | 判断项目或编排是否在白名单中 |
| selectByProjectId | Long projectId, Long orchestratorId | ProjectOrchestratorWhite | 查询白名单记录 |
| getWhiteListByProjectId | Long projectId | List<ProjectOrchestratorWhite> | 获取项目下所有白名单记录 |
| addProjectOrchestratorWhite | ProjectOrchestratorWhite | void | 添加白名单记录 |
| deleteProjectOrchestratorWhite | Long projectId, Long orchestratorId | void | 删除白名单记录 |

### 2.4 问题分析
- 前端目前直接屏蔽了项目复制和工作流复制功能，无法根据白名单动态判断
- 后端 `checkProjectAndOrchestratorIsWhite` 方法已存在，但没有独立的REST接口暴露给前端
- 需要新增一个独立的REST接口，前端在页面加载时调用，获取白名单状态

## 三、详细功能描述

### 3.1 功能范围

#### 3.1.1 核心功能
| 序号 | 功能名称 | 功能描述 | 优先级 |
|-----|---------|---------|-------|
| 1 | 项目白名单校验接口 | 提供接口判断指定项目是否在白名单中 | P0 |
| 2 | 工作流白名单校验接口 | 提供接口判断指定工作流是否在白名单中 | P0 |
| 3 | 前端动态控制复制按钮 | 前端根据接口返回结果动态显示/隐藏复制按钮 | P0 |

#### 3.1.2 扩展功能
| 序号 | 功能名称 | 功能描述 | 优先级 |
|-----|---------|---------|-------|
| 1 | 批量校验 | 支持一次请求校验多个项目/工作流的白名单状态 | P1 |

### 3.2 功能详情

#### 3.2.1 白名单校验接口设计

**接口路径**：`/dss/framework/project/checkIsWhite`
**请求方法**：GET
**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| projectId | Long | 是 | 项目ID |
| orchestratorId | Long | 否 | 编排ID（不传或传0表示校验项目级白名单） |

**返回参数**：

| 参数名 | 类型 | 说明 |
|-------|------|------|
| isWhite | Boolean | 是否在白名单中（true=在白名单中，false=不在） |

**返回示例**：
```json
{
  "method": "/dss/framework/project/checkIsWhite",
  "status": 0,
  "message": "OK",
  "data": {
    "isWhite": true
  }
}
```

#### 3.2.2 白名单校验规则
1. **项目级校验**：当 `orchestratorId` 为空或为0时，查询 `dss_project_orchestrator_white` 表中 `project_id = #{projectId} AND orchestrator_id = 0` 的记录，存在则为白名单
2. **工作流级校验**：当 `orchestratorId` 大于0时，查询 `dss_project_orchestrator_white` 表中 `project_id = #{projectId} AND orchestrator_id IN (0, #{orchestratorId})` 的记录，存在则为白名单（项目级白名单包含该项目的所有工作流）
3. **参数校验**：`projectId` 为空时返回 `isWhite = false`

#### 3.2.3 前端集成方式

**项目列表页面**（`#/workspaceHome`）：
- 页面加载时，对每个项目调用白名单校验接口（projectId=项目ID, orchestratorId=0）
- `isWhite = true` 的项目显示"复制项目"按钮
- `isWhite = false` 的项目隐藏"复制项目"按钮

**工作流页面**（`#/workflow`）：
- 页面加载时，对每个工作流调用白名单校验接口（projectId=项目ID, orchestratorId=工作流ID）
- `isWhite = true` 的工作流显示"复制工作流"按钮
- `isWhite = false` 的工作流隐藏"复制工作流"按钮

#### 3.2.4 权限控制
- 接口需要登录认证（SSO）
- 接口仅查询白名单状态，不涉及写操作
- 任何登录用户均可调用，白名单数据本身不受用户权限限制

## 四、验收标准

### 4.1 接口功能验收

#### 4.1.1 输入验证
- 传入有效的 projectId 和 orchestratorId
- 仅传入 projectId（不传 orchestratorId）
- 传入 projectId=0 或不传 projectId

#### 4.1.2 处理验证
- 在白名单中的项目/工作流，返回 `isWhite = true`
- 不在白名单中的项目/工作流，返回 `isWhite = false`
- 项目级白名单的项目，其下所有工作流均返回 `isWhite = true`

#### 4.1.3 输出验证
- 接口返回HTTP状态码200
- 返回JSON格式数据包含 `isWhite` 字段
- `isWhite` 值为布尔类型

### 4.2 项目复制按钮验收

#### 4.2.1 输入验证
- 用户进入项目列表页面

#### 4.2.2 处理验证
- 页面加载时调用白名单校验接口
- 白名单项目的"复制项目"按钮可见
- 非白名单项目的"复制项目"按钮隐藏

#### 4.2.3 输出验证
- 点击可见的"复制项目"按钮，弹出项目复制对话框
- 隐藏按钮的项目无法触发复制操作

### 4.3 工作流复制按钮验收

#### 4.3.1 输入验证
- 用户进入工作流页面

#### 4.3.2 处理验证
- 页面加载时调用白名单校验接口
- 白名单工作流的"复制工作流"按钮可见
- 非白名单工作流的"复制工作流"按钮隐藏

#### 4.3.3 输出验证
- 点击可见的"复制工作流"按钮，弹出工作流复制对话框
- 隐藏按钮的工作流无法触发复制操作

## 五、非功能需求

### 5.1 性能要求
- 接口响应时间 < 500ms
- 白名单查询走数据库索引，单次查询耗时 < 50ms
- 前端页面加载时批量调用不阻塞页面渲染

### 5.2 兼容性要求
- 向后兼容：不影响现有白名单相关接口的功能
- JDK版本兼容：JDK 8+
- 前端兼容：支持主流浏览器

### 5.3 安全要求
- 接口需要SSO登录认证
- 不暴露白名单详细内容，仅返回布尔值
- 防止接口被滥用（频率限制可后续考虑）
